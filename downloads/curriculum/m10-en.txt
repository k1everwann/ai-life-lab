Design a temperature alert

Open this lesson: https://k1everwann.github.io/ai-life-lab/en/index.html#lesson-automation

Test when a temperature rule should and should not send an alert.

Prepared example result

27°C: no alert. 28°C and 29°C: one each. Missing: to confirm. A repeated reading: no extra alert.

1. Make a first version

Practice material

This is a model-room alert exercise; it does not control real devices.
Rule: alert at 28°C or above; process each reading once; mark missing temperatures “to confirm”.
Readings in order: E01 = 27°C, E02 = 28°C, E03 = 29°C, E04 = missing, E02 = 28°C (received again).

Request for AI

For each reading, list its ID, whether it triggers an alert, and why. Give the total number of alerts.

1. Select “Copy material and request” below.
2. Paste into a new AI conversation and send.
3. Return and check the points below. Ask AI to correct any errors.

See a reference answer

E01: no alert. E02 and E03: one alert each. E04: to confirm, no alert. The repeated E02 was already processed, so no new alert. Total: 2.

Check these points

28°C triggers an alert; 27°C does not.
Receiving E02 again does not add another alert.
Missing data is not 0°C. The total is 2 alerts.

Avoid constant alerts

Three distinct readings: 10:00 = 28°C, 10:03 = 29°C, 10:05 = 28°C. No alerts were sent before these.

At 28°C or above, send an alert only if at least five minutes have passed since the last alert. Process these three readings and list the alert times.

Alert at 10:00, not at 10:03, and again at 10:05 when five minutes have passed. Total: 2.
