Stage 1 · Connect the file to what you see

Find, save, and reopen your HTML

  1. Create a practice folder, such as “My web practice.” Open your browser's download list and find the .html file from class. Use “Show in folder” to locate the actual file, then copy it into your practice folder.
  2. If your code is still in the lesson's full HTML field, use its HTML download button. If it is only in an AI reply, copy the complete code into a plain-text editor and save it as index.html using UTF-8. Do not use Word. In the Windows save dialog, select “All files,” show file extensions, and make sure the name is not index.html.txt.
  3. Open that file in a browser and check that its address points to your practice folder. Close the tab and reopen the file from the folder to confirm it is still there. Edit code in a text editor; view the result in a browser.
  4. If your classroom work is lost, download the prepared working example below and save it as index.html. It is a teaching example, not a project you have already completed.

Stage 2 · Turn a purpose into visible requirements

Your own topic, with at least three items

Choose a small purpose, such as a reading preparation checklist. Write down who will use it, what it helps them do, and at least three items. Use fictional or general text, such as “Choose a book / Prepare a notebook / Write down a question.” Do not use names, addresses, passwords, or private documents.

Before editing, copy index.html to index-before-topic.html. Replace the examples in this request with your own content. Give it to an available coding AI and limit its work to the file in your practice folder:

Please edit this single-file index.html.
Topic: My reading preparation checklist.
Purpose: Check that I am ready before reading.
Items: Choose a book, Prepare a notebook, Write down a question.
Keep the checkboxes, completed-item count, and reset-all button.
Do not add external packages, accounts, connections, tracking, or paid features.
Explain what you will change first. Then list tests I can perform myself.
If you reply with code in chat, provide the complete HTML, not just a snippet.
No AI available? Change only the visible text
  1. Open the downloaded working example in a plain-text editor. Find <h1> and replace only the heading between the opening and closing tags. You can also update the browser-tab name between the <title> tags.
  2. Find each item's text between <span> and </span> and replace it with your own. Keeping all four existing items is fine; you need at least three. Leave the tags, quotation marks, and script intact.
  3. Save, then refresh that same file in the browser. If you are using different HTML, find the corresponding heading and item text. When unsure, practice with the provided example.

Done when: Reopening the file shows your topic and at least three items, and you can explain its purpose in one sentence. Check two items, uncheck one, and reset all: the count must still go 2 → 1 → 0.

Stage 4 · Regression checks and backups

After the change, do the original features still work?

  1. Reopen: Save and close the project tab, then open the current index.html from its folder. Confirm your topic, at least three items, and the new instruction are there.
  2. 2 → 1 → 0: Start with Reset all. Check two different items: the completed count should be 2. Uncheck one: it should be 1. Reset all: it should be 0 with no checks remaining. Repeat once to catch incorrect accumulation.
  3. Narrow screen and keyboard: Narrow the browser to about 390px, or use its developer tools' device mode. Long text should wrap, the whole page should not scroll sideways, and buttons should remain visible. Tab to a checkbox and press Space; Tab to Reset all and press Enter. Check that focus is visible and the controls work. Browser simulation is not a test on a real phone.
  4. Make an identifiable backup: After tests pass, copy the file to index-good-YYYYMMDD-v1.html, using the actual date. Edit index.html next time and keep the working backup.
  5. Practice recovery: Open the backup to verify that it really works. If the current version breaks, first save it as index-broken.html to keep the problem for diagnosis. Copy the working backup back to index.html, reopen it, and repeat the first three checks. You do not need to delete the folder.

Download the blank learning log to record the filename, change, expected and actual results, and backup location. This is a text template for you to fill in; it does not inspect or back up your project. Edit and save it in a text editor.

Three different meanings of “save”

  • Save the HTML: Keep the code and default content. Being able to reopen the project does not mean it remembers yesterday's checkboxes.
  • Keep checked progress: Add code to remember checks in a particular browser. The original working example does not have this feature. This after-class page's own progress tracker does not add it to your project.
  • Publish a website: Separately place files on a website service so others can reach them through a URL. Downloading, backing up to cloud storage, or previewing a local file does not complete public publishing. Publishing is not required for this practice.

Done when: You have actual results for the tests and can open a working backup. Fix or restore any failures first; a checked box is not evidence of passing.

Advanced challenge: Remember checklist checks (Browser storage)

Start when: You have actually passed stage 4 and have a working backup. This is a feature specification to implement, not a capability already present in the original example. First understand the difference between reopening a file and remembering usage state.

Add an optional “Remember my checks” feature to my single-file checklist, off by default.
Use localStorage to save only stable item IDs and checked states, without personal data.
Changing a title or item order must not assign a check to the wrong item.
New items start unchecked.
When enabled, reloading the same address in the same browser restores checks and recalculates the count.
Reset all also clears saved checks; turning remembering off removes this project's record.
Never clear other websites' or exercises' data.
If storage is blocked or damaged, checking, unchecking, and counting must still work.
Show that saving is unavailable; do not claim success.
Do not add cloud services, login, or public publishing. Keep my topic and at least three items.

Test it yourself: Before enabling the feature, check two items and reload to verify that this feature is not saving them. Enable it, check two items, and reload: the count should stay 2. Uncheck one and reload for 1; reset and reload for 0. Reordering items must not mix up checks. Turning remembering off should stop persistence after reload. Ask a helper to test blocked and damaged storage and confirm interaction still works. Record any unperformed test as “Not verified.”

Browsers may restore form state themselves, so a single reload does not prove storage works. Storage support and scope for local file: pages vary by browser, and the lesson's isolated preview is not suitable for storage testing. If results are inconsistent, ask the instructor to help use a fixed local preview address and retest. Keep the version without progress saving until then.

Recovery: Back up before adding the feature. Keep the failed version and restore the working HTML if necessary. Browser records are separate from HTML: use the project's own clear function first, or ask a helper to remove only its storage key. Do not clear all website data. Backing up HTML does not automatically back up usage progress.

Without AI: Choose project A. In a backup copy, change only the topic and item text, sketch the grouping on paper, and write test steps. If you cannot add an interaction yet, keep the working version and your problem notes and ask the instructor for help. Do not record a sketch as completed software.

When you get stuck, check these first

The file opens as code, or I cannot find the download

Check that the actual extension is .html, then use “Open with” to select a browser. If the file is missing, use your browser's download list to locate it. If you only have code in a chat or a preview, return to stage 1 and save it.

I saved, but the page did not change

Confirm the editor has saved the file. Compare the browser address with the folder and filename you are editing; you may be viewing a backup. Refresh, or close the tab and reopen the edited file. Avoid editing multiple copies at once.

A button broke, and AI added lots of extra features

Save the failed version and restore your backup. Report one issue using the action, actual result, and expected result. Ask for only that fix, keeping your topic and items. Repeat stage 4 afterward, testing old features as well as the new change.

I only have a phone, or cannot use AI right now

Use the phone lesson's fictional notices: choose two, write a short request, and add one condition of your own. Check deadlines, sources, and unknowns against the text, then verify credibility with the original publisher. Without AI, edit the lesson's prepared draft. Save the result in a notes app and reopen it. This is useful practice on its own; use a computer later for file editing. You do not need to buy a tool.

If I send the HTML to a friend, will they see my checks?

They normally receive the code and default content. Browser progress is not automatically included in HTML or synced across devices. Use fictional content and explain what has and has not been tested before deciding whether to share.
